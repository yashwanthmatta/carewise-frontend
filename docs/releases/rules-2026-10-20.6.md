# Rules 2026-10-20.6: vitamin D3 names, repeated results and misread numbers

The protected tag `clinical-review-candidate-2026-10-20.2` and the .5 review pack in
`docs/clinical-validation-2026-10-20.5/` are unchanged. **These changes are not clinically
validated.** They need the same clinician review as .3 to .5 before they count as validated.

Version .6 holds three extraction safety fixes, all found by the independent reviewer on
2026-10-23 with synthetic reports. No threshold changed.

## 1. The "3" in "vitamin D3" is part of the name

Rules .5 stopped "Vitamin D, 25-hydroxy" with no result from being read as a vitamin D of 25.
The same kind of mistake still happened when the lab wrote the vitamin's form (D2, D3, D2+D3).
The digit in the name was read as the result:

| Report line | .5 read | .6 reads |
|---|---|---|
| `Vitamin D3 25 ng/mL 30-100 L` | 3 ng/mL | 25 ng/mL |
| `Vitamin D2+D3 (25-OH) 41 ng/mL 30-100` | 2 ng/mL (shown as low) | 41 ng/mL |
| `Vitamin D3, 25-hydroxy: 18.5 ng/mL` | 3 ng/mL | 18.5 ng/mL |
| `Vitamin D3` then `Pending` | 3 ng/mL (invented) | no value ("could not read the value") |
| `Vitamin D3 deficiency screen` then `Ferritin 45 ng/mL` | 3 ng/mL (invented) | no value |
| `25-OH Vitamin D2+D3` then `< 8 ng/mL` | 2 ng/mL | no value (the "<" result isn't read as a number) |

The vitamin D reader skips a D2/D3/D2+D3 suffix, and a result never starts right after a letter.
Wording changed: no. Pinned by 6 cases in `scripts/eval/heading-values.mjs`.

## 2. A repeated test lost its second, more concerning value

| Report text | .5 explained it as | .6 explains it as |
|---|---|---|
| `Potassium 4.1 mmol/L 3.5-5.1` / `Potassium 6.9 mmol/L 3.5-5.1` | Routine; "All 1 tests read from your report are within the lab's ranges" | Urgent: potassium 6.9 at a possible danger level, plus "More than one result" naming 4.1 |
| `Previous result: LDL cholesterol 98 mg/dL` / `Current result: LDL cholesterol 151 mg/dL <100 H` | "LDL appears around 98 mg/dL", "In a better range" | LDL 151, plus "More than one result" naming 98 |

When a test is printed again with a different value, the more concerning reading is used: the
higher one for LDL, total cholesterol, triglycerides and A1C, and for other tests a danger-level,
lab-critical or far-out-of-range reading over an in-range one. A new finding, "More than one
result", names the other value and asks the person to check with their doctor which is current,
and one doctor question is added. Goals ("LDL goal <100"), ratios ("LDL/HDL ratio 3.2") and
repeats of the same value don't count.
**New wording (English and Spanish)**: the "More than one result" finding and its question.

## 3. A number glued to letters was read as a result

| Report line (OCR misread) | .5 read | .6 reads |
|---|---|---|
| `Hemoglobin A1c S.9 % 4.0-5.6` (5.9) | A1C 9 %, "Clinician review important" | no value |
| `Glucose 1O8 mg/dL 70-99` (108) | glucose 1 mg/dL, "possible danger level", urgent | no value |

Dot leaders (`HbA1c.......5.9 %`) are still read. Wording changed: no.

## Where

The website's `script.js` and the phone app's `src/labPanel.ts` and `src/reportAnalysis.ts` are
changed in the same way. The website's lab-panel reader is regenerated from the app file. Web and
app give identical output on 197 reports (review cases, accuracy reports and adversarial cases).

## Effect on existing cases

All 160 review cases in `docs/clinical-validation-2026-10-20.5/validation-cases.csv` and the 68
accuracy reports were run through .5 and .6. Values, findings, risk level, urgent reasons and
questions were compared. **0 cases changed. Urgency changes: 0.** The comparison script does
report a change on the repeated-potassium report, so it is sensitive.

## Tests

- `scripts/eval/heading-values.mjs`: 6 vitamin D2/D3 cases, which fail on .5 and pass on .6.
- `scripts/eval/repeat-and-misread-values.mjs` (new, in CI): 11 cases for fixes 2 and 3,
  including the goal, ratio, same-value, urine-glucose and dot-leader guards.
- App `scripts/report_cases_check.js`: 5 new cases (32 in total).
- These still pass unchanged: accuracy eval (68 reports, 200 tests, 100%), 34 safety cases,
  photo-correction checks, and 10,000 random reports (5,000 standard and 5,000 hard, no failures).

## Still open (not changed in .6; needs a clinical decision)

- `LDL cholesterol <100 mg/dL` printed with no result is read as an LDL of 100, "In a better range".
- Two date columns on one line (`LDL cholesterol 98 151 mg/dL`) read the first (older) value.
- `Chest pain: none` / `Fainting: no` (negation after the symptom) counts as a current emergency
  symptom. This errs on the cautious side, and fixing it changes urgency behaviour.
- A result with no unit is shown with an assumed unit, and the missing unit isn't flagged.

## What the reviewer should do

1. Confirm the vitamin D cases in `scripts/eval/heading-values.mjs`.
2. Check that "More than one result" and using the more concerning reading are appropriate,
   using `scripts/eval/repeat-and-misread-values.mjs`.
3. Record the decisions in `docs/clinical-validation/validation-report-template.md`.
